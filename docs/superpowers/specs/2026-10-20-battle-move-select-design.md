# 战斗技能选择设计

## 目标

战斗时底部常驻显示当前上场宝可梦的技能按钮。玩家点技能出手；功能招真正结算；对手用简单 AI 选招。覆盖野生、训练家、双打、裂隙团战。

## 决策摘要

| 项 | 选择 |
| --- | --- |
| 功能招 | 回复 / 加攻 / 加防都进战斗结算 |
| 战斗范围 | 全部：1v1、双打、裂隙 |
| 界面 | 去掉「攻击」，底部常驻技能按钮 |
| 对手 | 简单 AI（回血、克制、强化、主力） |
| 双打选招 | 先第 1 只，再第 2 只，都选完再结算 |
| 架构 | 战斗状态挂在场上宝可梦上；结算函数接收选中招式 |

依赖已有的终点技能表（`js/final-move-kits.js`）。没有 `moves` 的物种仍用单个 `move`，界面只显示 1 个按钮。

## 场上战斗状态

每只场上宝可梦在进入战斗位时带上：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `usedUtility` | `false` | 这只是否已用过功能招 |
| `atkMul` | `1` | 攻击倍率 |
| `defMul` | `1` | 防御倍率 |

规则：

- 加攻把 `atkMul` 设为 `1.5`，加防把 `defMul` 设为 `1.5`，不叠层
- 功能招成功结算后设 `usedUtility = true`
- 换上场、开新战斗时重置这三项
- 存档的队伍数据不持久化这些字段；只活在当前战斗对象上

## 伤害

```
damage = max(1, floor(atk * atkMul * power / max(1, def * defMul) * typeMult))
```

功能招 `power === 0` 且带 `effect`，不走伤害公式。

## 技能按钮

- 用 `#move-buttons` 替换 `#btn-attack`
- 有 `moves`：按数组顺序渲染 2～3 个按钮
- 没有 `moves`：渲染那一个 `move`
- 攻击招文案：`名字 · 属性标签 · 威力 N`
- 功能招文案：`名字 · 回复|加攻|加防`
- `usedUtility === true` 时功能招按钮 `disabled`
- 「道具」「逃跑」位置与行为不变
- 忙碌 / 等待继续时禁用全部技能按钮（与现「攻击」一致）

### 双打

1. 提示「请为 {名字} 选择技能」
2. 玩家为第 1 只选一个技能（记入待执行指令，不立刻结算）
3. 切到第 2 只，再选一个
4. 两只都选完后，连同对手 AI 选招，一次调用 `resolveDualTurn`

只有一只还活着时，只选那一只。

### 裂隙团战

- 玩家选招后结算整回合
- 电脑队友仍自动使用各自的主力 `move`
- 头目用下方 AI（可使用功能招）

## 结算 API

### 1v1

`resolveTurn(player, foe, playerMove, foeMove, rng)`

双方按速度出手。功能招只改自身状态并写日志，不造成伤害。

### 双打

`resolveDualTurn(players, foes, playerMoves, foeMoves, rng)`

- `playerMoves` / `foeMoves`：与槽位对齐的招式数组（倒地槽位可为 `null`）
- 仍按速度排序；目标规则不变（优先同槽，否则第一个存活对手）

### 裂隙

`resolveSquadTurn(player, allies, foe, playerMove, foeMove, rng)`

- 玩家用 `playerMove`
- 盟友各自用主力
- 头目用 `foeMove`（单目标；不再过滤 `effect`）
- 道具回合 `resolveSquadItemTurn` / `resolveFoeOnlyTurn` / `resolveDualItemTurn`：敌方同样走 AI 选招

### 功能招日志示例

- `XXX 使用了 光合作用！回复了 N 点 HP！`
- `XXX 使用了 剑舞！攻击提升了！`
- `XXX 使用了 铁壁！防御提升了！`

回复量：`floor(maxHp * 0.5)`，不超过 `maxHp`。

## 对手 AI

输入：攻击方场上宝可梦、首选目标、可选招列表、`rng`。

只对带 `moves` 的物种跑分支；否则返回 `move`。

顺序：

1. 若 `hp / maxHp <= 0.4`，且未用过功能，且有 `effect === 'heal'` → 选回复
2. 否则，若覆盖招（第二格攻击招）对目标 `typeMultiplier > 1`，且主力对目标不是 `> 1` → 选覆盖
3. 否则，若 `rng() < 0.25` 且未用过功能，且有 `atk` 或 `def` 功能招：
   - 两者都有：`atk >= def` 种族值（物种 base）用加攻，否则加防
   - 只有一个：用那个
4. 否则 → 主力（第一格，或唯一的 `move`）

AI 在每个需要敌方出手的回合开始时选招，再传入结算函数。

## 数据流

1. 进战斗 / 换上场 → 给场上宝可梦补默认战斗状态 → 渲染技能按钮
2. 玩家点技能 → 1v1/裂隙：立刻结算；双打：写入槽位指令，第二只选完再结算
3. 结算前为每个活着的对手跑 AI
4. 播放日志与受击动画（复用现有 turn hit 播放）
5. `finishTurnOutcome` 照旧

## 测试要点

- `calcDamage` 带 `atkMul` / `defMul`
- 功能招 heal / atk / def 改状态且 `usedUtility`
- 已用功能招不能再结算第二次
- AI：残血选回复；克制选覆盖；否则偏主力
- 无 `moves` 的物种始终返回单招
- 双打需两道玩家指令才结算（可用纯函数测指令收集，不必驱动 DOM）

## 不做

- 不改 `TYPE_CHART`
- 不给初阶批量补三格技能
- 不做 PP、命中、异常状态、能力升降动画以外的视觉特效
- 不持久化战斗倍率到存档
- 不把电脑队友改成可选招或 AI 选招（仍打主力）
