# 双子塔 2v2 指令回合设计

## 目标

强化双子塔双打的操作感：玩家每回合为场上单位分别 **选招 + 按招式标签选目标**，并支持 **主动换人**。解决当前「几乎自动打、策略深度不足」的问题。

## 决策摘要

| 项 | 选择 |
| --- | --- |
| 优先问题 | 操作感 / 策略深度 |
| 指令模型 | 回合指令队列（两道指令齐再结算） |
| 目标体系 | 完整标签：`foe` / `ally` / `self` / `foes` / `allies` |
| V1 范围 | 仅双子塔（`battle.dual`）；含主动换人 |
| 换人 | 指令阶段完成上场；该槽本回合不攻击 |
| 其他模式 | 1v1 / 裂隙本规格不改 |
| UI 壳 | 不重做整套战斗界面；在现有底部操作上扩展 |

## 与既有规格的关系

- 扩展 `2026-10-20-battle-move-select` 的双打「两道指令再结算」与功能招场上状态（`usedUtility` / `atkMul` / `defMul`）。
- **依赖：** 若选招尚未落地，实现本规格时须一并带上双子塔技能按钮与功能招结算（可只做 `dual`，1v1/裂隙可仍用旧「攻击」直到选招规格全量落地）。
- 覆盖 `2026-10-17-twin-towers-design` 中「不做招式手动选目标 UI」的非目标：本规格明确做选目标与主动换人。
- 胜负、钥匙门槛、胜利后二选一捕捉等地图流程不变。

## 回合指令流程

仅当 `battle.dual === true`。

场上存活单位从左到右依次下指令：

1. 提示：`请为 {名字} 选择行动`
2. 底部提供：该只技能按钮、「换人」、现有「道具」「逃跑」
3. **选技能** → 进入目标选择（见下）→ 写入该槽指令 → 下一只
4. **选换人** → 打开后备列表 → 选定后该槽立刻换成新人，指令记为 `switch`（本回合不攻击）→ 下一只
5. 指令齐（仅一只存活则只下一道）→ 敌方 AI 选招+目标 → 一次 `resolveDualTurn` 结算

**道具：** 仍走现有入口；使用后本回合玩家不攻击，敌方照常出手（扩展后的 `resolveDualItemTurn`，敌方带目标 AI）。

**重选：** 给第二只下指令时，可「重选上一只」：清除上一道指令并回到上一只的行动选择。

**强制换人（击倒后）：** 结算结束后若有空槽且有后备 → 现有补位 UI；补位单位从 **下一回合** 才开始下指令。

## 招式目标标签

招式字段 `target`：

| 值 | 含义 | 点选 |
| --- | --- | --- |
| `foe` | 敌方单体 | 高亮敌方存活位，点一只 |
| `ally` | 己方单体（含自己） | 高亮己方存活位，点一只 |
| `self` | 仅自己 | 不进点选，自动锁自身 |
| `foes` | 敌方全体 | 高亮敌方；点任意合法位或确认一次 |
| `allies` | 己方全体 | 同上，对己方 |

**缺省：**

- 有伤害且无 `effect` → `foe`
- 有 `effect`（回复 / 加攻 / 加防）→ `self`
- 显式 `target` 覆盖缺省

**V1 内容：**

- 现有攻击/功能招靠缺省即可跑通
- 双子塔 8 传说：主力/覆盖为 `foe`，功能为 `self`
- 额外给 2～4 个招打上 `foes`，验证全体逻辑；不批量给全图鉴加 AOE

**点选交互：**

1. 点技能后合法目标加 `targetable`；非法位变暗不可点
2. 提示：`选择目标` / 全体时说明将打击该侧全体
3. 「返回」回到该只行动选择，清除未确认技能
4. 合法目标仅剩 1 个时自动选中并跳过点选

## 结算规则

所有本回合攻击单位（玩家 `move` 指令 + 敌方）按 **速度降序**；同速玩家优先，再比槽位。

| 指令 | 行为 |
| --- | --- |
| `move` + `foe`/`ally` | 打指定目标；若已倒，改打同侧第一只仍存活者 |
| `move` + `foes`/`allies` | 对结算当下该侧所有存活单位各结算一次 |
| `move` + `self` | 只作用于自己；功能招规则与选招规格一致 |
| `switch` | 不参与速度排序攻击；上场已在指令阶段完成 |

主动换人细节：

- 旧单位离场，HP/状态写回队伍
- 新单位进同槽，战斗状态重置（`usedUtility` / `atkMul` / `defMul`）
- 本回合不攻击；下回合正常选招
- 一轮内两只都可换，或一只打一只换
- 不可选：已在场上、HP≤0、非现役

## 敌方 AI（双子塔）

每只存活 Boss 独立选择：

1. `hp/maxHp <= 0.4`，未用过功能，且有 `effect === 'heal'` → 回复（`self`）
2. 否则在攻击招中，对优选目标算克制：覆盖招更克制则选覆盖
3. 约 25% 且未用过功能：选加攻/加防（两者都有时按种族攻防倾向）
4. 否则主力

**优选单体目标：** 先同槽玩家；同槽已倒则另一只；两只都在时选该招倍率更高者，相同则同槽。

`foes`：选中即打双方，无点选。

## API 形态

```text
resolveDualTurn(players, foes, playerCmds, foeCmds, rng)
// cmd: { type:'move', move, targetSide, targetIndex }
//    | { type:'switch' }
//    | null   // 倒地槽
```

功能招伤害/倍率公式、日志文案与 `2026-10-20-battle-move-select` 一致；日志需带清目标信息（打向谁 / 横扫谁）。

## UI 状态机

| 阶段 | 界面 | 可点 |
| --- | --- | --- |
| `cmd-action` | 当前槽技能 + 换人 + 道具/逃跑 | 选技能或换人 |
| `cmd-target` | 场上高亮合法目标；返回 | 点目标或返回 |
| `cmd-switch` | 主动换人列表 | 选一只或取消回 `cmd-action` |
| `resolving` | 忙碌全禁 | 等日志/受击 |
| `force-switch` | 击倒后补位 | 有后备时必选一只 |

- 提示条标明当前单位与阶段（行动 / 目标）
- 已下完指令的槽位标记「就绪」
- 「重选上一只」仅在第二只的 `cmd-action` 出现

## 数据与代码落点（实现时）

- `js/battle.js`：扩展 `resolveDualTurn` / `resolveDualItemTurn`；目标解析与回退
- `js/game.js`：双子塔指令状态机、目标高亮、主动换人、与选招按钮衔接
- 招式数据：`target` 缺省逻辑 + 少数 `foes` 抽样
- `index.html` / `css/game.css`：目标高亮、就绪标记、重选/返回
- `tests/`：指令收集、目标回退、换人不攻击、全体命中存活者

## 非目标（V1）

- 1v1 / 裂隙的选目标与主动换人
- PP、命中、异常状态、正式双打特有规则（保护、击退、帮助等）
- 道具指定治疗目标（仍自动选亏血最多者）
- 全图鉴批量 AOE
- 重做整套战斗壳式菜单 UI

## 验收

1. 双子塔每回合可为两只分别选招，并按标签选目标后才结算
2. `self` 不进点选；合法目标仅 1 个时自动跳过点选
3. 主动换人后新人当场上场且本回合不攻击；可与另一只攻击同回合组合
4. 原目标倒下时单体招改打同侧存活者；`foes` 打结算时仍存活的全体
5. 敌方按简单 AI 选招与单体目标
6. 击倒强制补位、胜负与选抓流程不变
7. 相关单测通过；`npm test` 通过
