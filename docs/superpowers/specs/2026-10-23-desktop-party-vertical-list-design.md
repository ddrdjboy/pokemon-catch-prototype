# 大屏「我的宝可梦」改为纵向列表

日期：2026-10-23  
状态：已确认

## 问题

选图页右侧「我的宝可梦」当前在所有宽度下都是**紧凑方卡 + 横向滚动**。电脑和 iPad 上这种手机式横滑不合适，应改为更易浏览的纵向列表。

## 目标

1. **宽屏（`min-width: 721px`，电脑 / iPad）**：队伍区改为纵向长卡片列表，栏内上下滚动；不再横向滚动。
2. **窄屏（`max-width: 720px`，手机）**：保持现有方卡横滑，行为与视觉不变。
3. 不改变排序 / 收回 / 上场 / 详情等交互语义，仅改大屏卡面排版与列表流向。

## 非目标

- 不恢复「胶囊 / 瓷砖 / 双段」三种 `partyStyle` 切换（线上已移除）。
- 不改选怪屏 `#pick-party` 布局。
- 不改对战、捕捉、存档字段或队伍容量规则。
- 不改选图页左右分栏结构（左地图、右队伍）。

## 布局

### 宽屏（≥721px）

- 选图页仍为横向 `row`：左「选择地图」、右「我的宝可梦」。
- `#party-list`：`flex-direction: column`（或等价纵向堆叠），`overflow-x: visible`，取消单行横滑；纵向滚动由外层 `.pane-scroll` 承担。
- `.party-card`：改回横向条卡——左侧立绘框，右侧名称 / 等级（及现有角标、出场态描边）；宽度跟随栏宽（`width: 100%` 或 `flex: 1 1 auto`），固定方卡宽度（如 88px）仅保留给窄屏。
- 卡片上的操作弹层（popover）继续相对卡片定位；需确认在纵向列表 + `pane-scroll` 下不被裁切（沿用现有「弹层叠在卡片 inset 内」策略，避免依赖卡片外 overflow）。

### 窄屏（≤720px）

- 维持现有：`#party-list` 横向 `flex` + `overflow-x: auto`；方卡固定宽度。
- 不引入纵向列表样式。

### 断点

沿用现有 **720px** 媒体查询分界，不新增断点：

| 视口 | 队伍列表 |
|------|----------|
| ≤720px | 方卡横滑（现状） |
| ≥721px | 纵向长卡片 + 上下滚（本改动） |

## 交互

- 点击卡片打开操作入口：左移 / 右移 / 收回|上场 / 详情等，逻辑与现实现一致。
- 出场前 6 只的视觉区分（描边 / 角标）在长卡片上保留。
- 不新增设置项或存档字段。

## 文件改动（预期）

| 文件 | 改动 |
|------|------|
| `css/game.css` | 在 `@media (min-width: 721px)`（或等价宽屏规则）中覆盖 `#screen-select .party-list` / `.party-card` 及其子元素为纵向列表样式；确保窄屏规则不被破坏 |
| `index.html` | 仅当现有 class 不足以区分「选图队伍列表」时做最小 class 补充；默认不改 |
| `js/game.js` | 默认不改；仅当弹层在纵向列表下定位失败时做最小修复 |

## 测试要点

1. 宽屏（桌面或 iPad 宽度 ≥721）：选图页右侧队伍为纵向列表，可上下滚动，**无**横向滚动条 / 横滑手势需求。
2. 窄屏（≤720）：仍为方卡一行横滑，与改前一致。
3. 宽屏点卡：操作弹层可用，排序 / 收回 / 上场 / 详情仍正确。
4. 出场态描边与等级信息在长卡片上可见。
5. `#pick-party` 选怪布局与改前一致。
6. 硬刷新线上或本地静态页，确认缓存参数不影响本次纯 CSS 改动（若改 HTML 链 CSS 版本号则一并 bump）。

## 实现顺序建议

1. 在宽屏媒体查询中覆盖 `#party-list` 流向与 overflow。
2. 覆盖 `.party-card` 为横向条卡（立绘 + 文案）。
3. 对照窄屏回归横滑。
4. 点选弹层与出场态目视检查。
